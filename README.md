# БРЕДОВУХА

Онлайн-игра для вечеринок в духе Fibbage. Ведущий выводит на экран реальный абсурдный факт с пропуском. Игроки с телефонов вписывают правдоподобную ложь, а потом ищут среди выдумок правду.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | Разметка и стили (Tailwind CDN, неоновый дизайн) |
| `js/questions.js` | 150 вопросов: 6 паков по 25 |
| `js/app.js` | Сеть, игровой цикл, очки, звук, каталог |

Сборка не нужна: всё работает как статический сайт.

## Ведущий тоже может играть

При создании комнаты оставьте включённой галочку «🎮 Я тоже играю с этого устройства». Её можно переключить и в лобби. Тогда на экране ведущего будет его собственный пульт и над ним полоса управления комнатой. Комнату можно создавать прямо с телефона.

Важно: устройство ведущего хранит всю игру. Если свернуть браузер или заблокировать телефон, игра встанет у всех. Когда ведущий вернётся на страницу, игра продолжится с того же места.

## Как устроена сеть

Игра подключается ко всем каналам сразу. Если один канал недоступен, работают остальные. Дубликаты сообщений отсеиваются.
- **Свой сервер в Yandex Cloud** (`server/`). Это основной канал: из России он работает без замедлений. API Gateway держит WebSocket-соединения, а функция `bred-relay` пересылает сообщения. Сервер не хранит игру, он помнит только соединение ведущего каждой комнаты: это крошечный файл в Object Storage. Список игроков для рассылки сервер получает от ведущего.
- **Публичные MQTT-брокеры** (запасные): `broker.emqx.io`, `test.mosquitto.org` и `broker.hivemq.com`.
- `BroadcastChannel` для тестов во вкладках одного браузера.
- Отладочный режим: `?net=relay` в адресе. Тогда игра работает только через сервер в Яндексе, без MQTT и без связи между вкладками.
- Всё состояние хранит ведущий и рассылает его игрокам. Каждое действие игрока пронумеровано и повторяется, пока ведущий его не подтвердит.
- Тексты лжи, голоса и авторство не уходят в сеть до вскрытия.
- Перезагрузка вкладки игрока возвращает его в игру. Ведущий может продолжить незакрытую комнату после перезагрузки.

## Сервер в Yandex Cloud

Сервер разворачивает GitHub Actions (`.github/workflows/deploy-relay.yml`) при каждом изменении в `server/`. Ключи не используются: GitHub подтверждает Яндексу, что запуск идёт из этого репозитория, через федерацию сервисных аккаунтов. Сервисный аккаунт `github-deploy` привязан к веткам `main` и `claude/lucid-morse-20daf0`.

Сценарий `server/deploy.sh` можно запускать повторно. Он создаёт или обновляет:
- сервисный аккаунт `bred-relay-sa`;
- бакет `bred-relay-<каталог>`;
- функцию `bred-relay`;
- шлюз `bred-relay-gw`.

Адрес шлюза записан в `RELAY_URL` в `js/app.js`.

## Проверка на своём компьютере

```bash
python -m http.server 8000
```

Откройте http://localhost:8000, создайте комнату и нажмите «🧪 Тест-игрок», чтобы открыть пульты игроков в соседних вкладках.

## Публикация на GitHub Pages (чтобы друзья заходили с телефонов)

1. Создайте на GitHub пустой публичный репозиторий, например `bredovuha`.
2. В этой папке выполните:

```bash
git init
git add index.html README.md js
git commit -m "Бредовуха: онлайн-версия"
git branch -M main
git remote add origin https://github.com/<ЛОГИН>/bredovuha.git
git push -u origin main
```

3. На GitHub откройте Settings → Pages → Source: «Deploy from a branch» → Branch `main`, папка `/ (root)` → Save.
4. Через 1–2 минуты игра будет доступна по адресу `https://<ЛОГИН>.github.io/bredovuha/`.
